Design Draft · v0.1

Her-Bench 设计草案

评测 agent「陪看长游戏直播」的能力：在具体时间点上看懂画面、答对问题、查对资料。

一、素材：三个「首次盲玩」系列

已下载的三个来源有个共同点：主播都是第一次玩。Minecraft 那个系列甚至叫 "No Wiki"——故意不查资料。盲玩意味着玩家会犯错、卡关、误解机制，这些时刻天然就是出题点：玩家不知道的，正是 agent 该替观众解释或去查的。

游戏主播已下载时长素材特点
Portal / Portal 2Mapocolops第 1–6 集~9.6 h解谜盲玩，卡关和顿悟时刻密集，剧情驱动
Minecraft (No Wiki)About Oliver第 1–3 集~8.1 h开放世界，明确拒查 wiki，知识盲区最多
Human Fall FlatiShoyaPart 1 全片~4.1 h物理解谜，失败反复多，攻略资料少

视频均为 720p mp4，无章节信息（chapters 为空），时间锚点需要标注阶段自己产出。完整 playlist 共 ~202 小时，后续可按需扩量。

二、资料生态：三档天然梯度

三个游戏的公开资料丰富度差异很大，正好构成 retrieval 难度的三档梯度——同一种任务，在资料多和资料少的游戏里考察的能力不一样。

Rich

Minecraft

minecraft.wiki 覆盖所有物品、生物、机制，配方可精确核对；教程视频和 Reddit 讨论海量。答案有权威出处，适合出可判定的事实题。

Medium

Portal 系列

theportalwiki.com、Combine OverWiki 覆盖道具与关卡；Steam Community guides 和逐关 walkthrough 视频齐全，但粒度比 Minecraft 粗。

Sparse

Human Fall Flat

没有像样的 wiki，只有零散的关卡视频和 Steam guides。适合考「查不到怎么办」：从视频画面本身推理，或承认资料不存在。

三、任务形态：一个 task 一个 container

沿用 WildClawBench 的框架：每个 task 打包成一个可复现的 Docker container，里面跑真实的 agent harness，工具是真的，不是 mock。区别在于我们的输入是带时间锚点的直播录像，工具偏向看帧和查资料。

四、五类任务，锚在真实时间点上

下面两帧截自已下载的 Portal 盲玩视频，示意「问题挂在时间戳上」长什么样：

类型例子主要考察
指认解释“他刚捡的这个道具是干啥的？”视觉 grounding + 检索核实
错误诊断“他卡了十分钟，哪一步理解错了？”对比玩家行为与正确解法
攻略建议“接下来该查什么才能过这关？”主动检索、给可操作建议
跨时段记忆“他第一次遇到 turret 是几点？当时什么反应？”长视频记忆与定位
资料检索“找一篇讲这个机制的资料，给出处并总结”检索质量、引用可验证

五、Task schema（草案）

{
  "task_id": "portal-e01-0042",
  "video": "portal/01_...eag0XgV41-8.mp4",
  "anchor_sec": 900,
  "context_window_sec": [0, 900],      // 只允许看锚点之前的内容
  "question": "他手里这把枪是干什么的？两种传送门有什么区别？",
  "type": "identify_explain",
  "resources": {
    "mode": "live_search | offline_pack",   // 复现实验用离线包
    "offline_pack": ["theportalwiki.com/wiki/Portal_Gun", "..."]
  },
  "grading": {
    "rubric_points": ["发射蓝橙两个门", "两门互通", "只能打在白色墙面"],
    "must_cite_source": true,
    "judge": "vlm"
  }
}

两个关键约束：只看锚点之前（模拟直播陪看，不能剧透未来）；live_search / offline_pack 双模式（前者贴近真实，后者保证可复现，参照 WildClawBench 的容器化思路）。

六、下一步

  1. 对已下载的 ~22 小时跑 ASR（主播解说是重要信号源），产出带时间戳的转写。
  2. 用 VLM 粗扫视频，自动圈出候选锚点：捡到新道具、卡关、死亡、剧情节点。
  3. 人工从候选里挑锚点写题，每类任务先各写 ~10 个，凑 50 题的 pilot 集。
  4. 给每题抓离线资源包，打包 container，先拿现有 agent 跑通评分脚本。
