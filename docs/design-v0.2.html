Design Draft · v0.2

Her-Bench 设计草案

只讲两件事：一个 container 里装什么；一个 task 长什么样、考什么、怎么打分。
思路背景见调研笔记《游戏陪玩与实时交互》。

Part 1

一个 container 里装什么

container 按视频组织：一个视频一个 container，里面挂 5–10 个 task。所有 task 共享同一份视频、转写和资源包，只是各自锚在不同时间点。这样评一个 container 只需加载一次素材，也保证同视频内的 task 可以考「跨时段记忆」。

锚点是怎么分布的

一个视频的时间线上标出若干事件锚点（拿到新道具、卡关、死亡、剧情点），task 挂在锚点上。下面两帧来自已下载的 Portal 盲玩 ep01：

Part 2

一个 task 长什么样

task 分两类，对应两组能力：

类型输入agent 要做的事
问答型视频播到锚点 t，用户提一个问题看画面 + 查资料，给出正确且不剧透的回答（比如只给方向性提示，不直接给完整解法）
主动型视频播到某一段，没有人提问自己判断该不该开口、什么时候开口、说多少——玩家卡关够久才提示，正常游玩时保持沉默

agent 考什么：四个环节，每个都能单独挂掉

  1. 看懂画面：认出锚点处的道具/敌人/状态（视觉 grounding）；
  2. 记住看过的：答案可能依赖几十分钟前的画面（跨时段记忆）；
  3. 查对资料：从资源包/白名单站点检索到支撑答案的来源；
  4. 说得恰当：查到了完整攻略，但融合成提示时只说该说的——「查对了但说过头」是独立的失败模式，单独计为剧透违规。

怎么打分：信息质量 + 时机，两组指标

指标量什么判分方式
信息质量（两类 task 都算）
rubric_hit答案要点命中率（每题预写要点清单，如「蓝橙两个门互通」）规则 + judge
grounding_acc画面里的东西指认对没对VLM judge
citation_valid引用的来源真实存在、且确实支撑答案规则
spoiler_violation剧透违规：泄露锚点之后的剧情，或直接给出完整解法judge
时机（主动型 task 为主）
window_hit开口时刻落没落进标注的时间窗口（早了剧透、晚了没用）规则
time_diff开口时刻与理想时刻的偏差秒数（窗口内再细分好坏）规则
over_trigger过度介入：不该开口的静默段里开了几次口，单独扣分规则
latency从触发到给出回应的真实耗时（含检索），超时降档规则

task 文件（草案）

{
  "task_id": "portal-e01-t03",
  "type": "query | proactive",
  "anchor_sec": 900,
  "context_window_sec": [0, 900],     // 工具只能访问锚点之前
  "question": "他手里这把枪是干什么的？",   // proactive 型没有此字段
  "response_window_sec": [880, 940],   // proactive 型的开口窗口
  "hint_level": "direction_only",      // 提示分级：只给方向，不给解法
  "resources_mode": "offline_pack | live_search",
  "grading": {
    "rubric_points": ["发射蓝橙两个门", "两门互通", "只打在白色墙面"],
    "spoiler_blocklist": ["GLaDOS 的结局", "第 19 室之后的内容"],
    "must_cite": true
  }
}

汇总方式：每个 task 输出信息分（rubric_hit × 引用 × 无剧透）和时机分（window_hit − over_trigger 惩罚）两个数，不合成单一总分——两个能力轴本来就该分开看，一个模型可能答得准但抢话，另一个安静但答不对。
