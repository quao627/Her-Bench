Diagram · Her-Bench

出题逻辑与 Rubric 设计

一道题怎么从视频里找出来、写成什么样，判分按什么标准。
两套题：主播开口问的那套在 Part 1-3，全程不给声音的纯 proactive 那套在 Part 4。

Part 1

题目从哪里来

每道题都对应视频里实际发生的一件事：一个谜题、一次卡关、一次操作失误。 多个 agent 分段扫视频找出候选，另一批 agent 独立复核，人再挑一遍。

锚点怎么定

每个候选锚点都要 ffmpeg -ss <t> -frames:v 1 截一帧核对。 scene 写的是这一帧画面上有什么。转写用来定位大概位置，具体是哪一秒要看画面。

锚点还要落在证据已经出现的那一刻。context_window_sec 只能看到锚点之前，所以「过关了」这种要靠场景切换才看得出来的事，锚点必须推到变化之后， 否则这道题在自己的可见窗口里无解。

验证的六项检查

提出和验证由不同的 agent 做，出题的 agent 不复核自己出的题。

检查项不通过的典型形态
可答性rubric 引用了锚点之后才出现的画面，相当于要求 agent 知道锚点之后的事
非 trivial答案在转写里被主播自己说出来了，照着复述一遍就能得分
剧透question 或 scene 本身泄露了锚点之后的剧情
撞车与已有锚点间隔过近，或考的是同一件事
rubric 可判写成「回答得体」这类无法客观勾选的描述
编造要求 agent 说出视频没交代的具体原因；只给了结果时 rubric 必须要求它承认不确定

Part 2

一个 task 的骨架

两种类型都挂在同一条时间轴上，锚点之后的内容一律不可见。

query 主播问

主播开口问了一个问题，用他的第一人称写。评的是回答是否准确、有没有剧透、需要引用时有没有给出来源。

proactive 该不该说

没人问，但画面里发生了值得提醒、安慰或庆祝的事。评的是开口时机是否落在窗口内，以及说的内容是否有用。

hint_level: direction_only

只给方向，提醒该往哪想、该留意什么，不给完整解法步骤。

hint_level: full

可以把原理、步骤、容易搞错的地方完整讲清楚。

Part 3

Rubric：按什么打分

字段作用
rubric_points 一组要点 checklist，命中几条打几分，不对回答整体做模糊评价
spoiler_blocklist 锚点之后才会出现的内容，答案里出现直接扣分
must_cite 为真时不允许只凭记忆回答，判分看有没有真的调用查证工具并给出来源
tool_fit 标记这题适合考查证能力。它和 must_cite 为真的题会强制触发查证，不依赖模型自己决定

回答是否正确和有没有真的查证是分开判的。对话式模型容易把没有查过的内容说得像查过一样， must_cite 就是针对这一点设的。查证怎么强制触发见另一张图 陪看双引擎。

Part 4

纯 proactive 那一套

上面那套题多数是 reactive 的：主播开口问了，agent 才答。另有一套反过来： 评测时不给原声、不给转写、不给题目，agent 只有每隔几秒一张画面，什么时候开口全由它自己判断。 题也就得换一种出法。

上面那套纯 proactive
agent 收到什么直播原声 + 画面 + 到锚点时的任务包只有画面帧
题的时间一个锚点一段窗口，窗口内开口才算接住
题从哪来分段扫视频找事件扫画面 + 挖转写两条路
转写的角色定位大概位置出题时用，评测时 agent 一个字看不到

两条出题路

分工是：画面决定这算不算一道题、窗口在哪，因为 agent 也只有画面，这样才公平； 转写决定什么才叫帮到了，他自己说出来的困惑，是写 help_points 最准的依据。

扫画面问的是一个可答的问题：从第一帧到最后一帧，他推进了吗。换区域了、界面切了、 HUD 数字动了，就是推进；几帧下来还在同一片地方转、同一个菜单一直开着、同一个动作反复失败， 就是没推进。没推进就是这一局要找的东西。这条路不需要字幕，也能找到他压根没吭声的时刻。

挖转写捞的是画面上不显眼、但他自己说破了的时刻。提候选的模型看不到画面， 所以它只写「如果这事是真的，画面上应该能找到什么」，接着必须过一次截帧复核。 刷掉的比留下的多是有意的：只在嘴上抱怨、画面上完全没痕迹的时刻，对一个只有画面的 agent 是无解题。

evidence 有两种含义

每道题都存了那一段的主播原话，但两条路的含义不一样，别混着看：

来路evidence 是什么
挖转写出题的理由本身。是这几句话让人判定他需要帮助的
扫画面只是那一段时间他说了什么，顺手存下来当参考，有时跟这道题没关系

两种都只给判分员看。被测的 agent 一个字都看不到，否则这套评测就没意义了。

怎么判

先判时机：窗口内开口算接住，同一个窗口只认第一句，记晚了多少秒；所有窗口之外的发言逐次记成多余。 接住之后再判说得有没有用，走的是跟上面同一个判分器，只是把 help_points 当 rubric、 must_not_say 当防剧透清单。
