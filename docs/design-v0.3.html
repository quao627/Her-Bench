Design Draft · v0.3

Her-Bench 设计草案

只讲两件事：一个 container 里装什么；一个 task 长什么样、考什么、怎么打分。
思路背景见调研笔记《游戏陪玩与实时交互》。

Part 1

一个 container 里装什么

container 按视频组织：一个视频一个 container，里面挂 5–10 个 task。所有 task 共享同一份视频、转写和资源包，只是各自锚在不同时间点。这样评一个 container 只需加载一次素材，也保证同视频内的 task 可以考「跨时段记忆」。

Part 2

一个 task 长什么样

task 分两类，对应两组能力：

类型输入agent 要做的事
问答型视频播到锚点 t，用户提一个问题看画面 + 查资料，给出正确且不剧透的回答
主动型视频播到某一段，没有人提问自己判断该不该开口、什么时候开口、说多少

走查一个问答型 task：portal-e01-t03

视频播到 15:00，用户问：「他手里这把枪是干什么的？」。agent 能看到的是锚点之前的全部画面——理解问题要靠这段上下文（枪是 13:58 才捡到的）：

「查对了但说过头」是独立的失败模式

两个回答检索到的是同一篇 wiki，要点全对——差别只在融合成回答时说了多少：

主动型 task：考的是「该不该开口」

没有用户提问。标注给出一段含卡关事件的时间线，agent 全程观察、自己决定开口时机。判分看两件事：开口时刻落没落进窗口（window_hit / time_diff），以及不该开口的地方开了几次（over_trigger）：

指标汇总

指标量什么判分方式
信息质量（两类 task 都算）
rubric_hit答案要点命中率（每题预写要点清单）规则 + judge
grounding_acc画面里的东西指认对没对VLM judge
citation_valid引用的来源真实存在、且确实支撑答案规则
spoiler_violation泄露锚点之后的剧情，或给出超过 hint_level 的解法judge
时机（主动型 task 为主）
window_hit开口时刻落没落进标注窗口规则
time_diff开口时刻与理想时刻的偏差秒数规则
over_trigger不该开口的静默段里开了几次口，逐次扣分规则
latency从触发到给出回应的真实耗时（含检索），超时降档规则

task 文件（草案）

{
  "task_id": "portal-e01-t03",
  "type": "query | proactive",
  "anchor_sec": 900,
  "context_window_sec": [0, 900],     // 工具只能访问锚点之前
  "question": "他手里这把枪是干什么的？",   // proactive 型没有此字段
  "response_window_sec": [880, 940],   // proactive 型的开口窗口
  "hint_level": "direction_only",      // 提示分级：只给方向，不给解法
  "resources_mode": "offline_pack | live_search",
  "grading": {
    "rubric_points": ["发射蓝橙两个门", "两门互通", "只打在白色墙面"],
    "spoiler_blocklist": ["GLaDOS 的结局", "第 19 室之后的内容"],
    "must_cite": true
  }
}

汇总方式：每个 task 输出信息分（rubric_hit × 引用 × 无剧透）和时机分（window_hit − over_trigger 惩罚）两个数，不合成单一总分——两个能力轴本来就该分开看，一个模型可能答得准但抢话，另一个安静但答不对。
