# 评测协议

评测这一侧起一个 HTTP 服务，手里攥着视频和时钟。agent 是另一个进程，连进来取画面、
自己开口。地址从环境变量 `HERBENCH_WORLD` 拿（形如 `http://127.0.0.1:53412`）。

## 端点

### `GET /session`

这一场是什么。开跑前叫一次就够。

```json
{"container": "portal-e01", "title": "Portal · 首次盲玩全流程（Mapocolops）",
 "video_sec": 1300, "frame_step": 5}
```

### `POST /tick`

往前走一格。请求体可以是空的。

```json
{"done": false, "t": 630.0, "video_sec": 1300,
 "frame": "<base64 jpeg>",
 "event": {"type": "question", "text": "我刚拿到的这个装置是干什么用的？",
           "at": 630, "late_sec": 0.0}}
```

- `t` 当前视频时间（秒）
- `frame` 这一刻的画面，base64 JPEG
- `event` 为 `null` 表示这一刻没人说话；`{"type":"question"}` 表示主播开口了，
  **下一步应该 `/say` 回话**。`late_sec` 是这句话在视频里说出口之后隔了多久才递到
  你手上——你上一格想太久的话，这个数就不是 0
- `done` 为 true 表示视频走完了，退出循环

**没回话就再 tick 会被记成放弃作答。**

### `POST /say`

```json
{"text": "这是传送门枪，现在这版只能打蓝门……"}
```

在当前视频时间说一句。有待回的问题时算作答，没有时算主动开口，两种都记。
空字符串不算。

### `GET /result`

跑完之后取原始记录：说过哪些话、答了哪些题、用了多少视频时间、错过多少帧。
判分不在这里，由评测那一侧另做——agent 看不到自己的分。

## 时钟

每次 `/tick`，视频时间前进：

```
max(帧间隔, 你上次拿到响应到这次发请求之间的墙钟时间)
```

所以：

| | |
|---|---|
| 想得快 | 每次前进一帧，看到每一帧，整场跑完远快于视频本身 |
| 想得慢 | 按你自己的耗时前进，中间的帧**直接错过**，问题也要等你回来才拿得到 |

后台线程随便开，但那些时间一样会在下一次 `/tick` 上体现出来——你在后台跑一次
20 秒的检索，视频就往前走了 20 秒，这段时间发生的事你没看见。

这不是为了惩罚谁。真实场景里视频本来就是往前走的，一个想得慢的 agent 就是会错过
时机，协议只是把这件事如实记下来。

## 边界

- 一次只有一个 agent 连进来，`/tick` 之间没有并发保证
- 视频走完之后所有 `/tick` 都返回 `done`
- agent 崩了或者卡死不算评测的问题，`run_eval.py` 会照实报出来
